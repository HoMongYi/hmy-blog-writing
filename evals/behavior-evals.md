# 행동 평가와 확인 범위

평가 절차와 실행 상태를 구분한다. 항목을 나열했다고 통과한 것은 아니다. 테스트에는 공개 가능한 합성 입력을 사용하며 비공개 원고·사용자 답변·CMS 데이터는 포함하지 않는다.

## 짧은 입력으로 확인할 동작

새 작업 폴더에 패키지를 설치하고 실제 사용한 스킬 파일을 기록한다. 파일 설치, 자동 검색, 참조 읽기, 모델 실행을 각각 확인한다. 필요한 참조만 제공하며 예상 출력은 평가 대상에게 주지 않는다.

| 입력 사례 | 확인할 점 |
| --- | --- |
| 개인적인 생각: 합성 메모에 ‘연말 목표를 여러 개 적기보다 하나를 고르고 싶다’만 제공 | 없던 과거 실패·행동·감정을 만들지 않고 그 생각을 풀어 쓰는가 |
| 생활용품 후기: 가상 컵받침을 이틀 사용했고 표면의 물방울을 닦았다는 기록만 제공 | 흡수력·내구성·만족감을 관찰한 것처럼 추가하지 않는가 |
| 비기술 정보: 가상 전시 안내에 ‘토요일 14시 시작, 예약 필요’만 제공 | 종료 시각·입장료·장소·개인 방문 경험을 만들지 않는가 |
| 기술 설명: 가상 장치 A의 설명서에 입력 전압 5 V, 12 V 전원 연결 금지만 제공 | 수치·모델 범위·금지 조건을 보존하고 실측·고장 원인을 만들지 않는가 |

부분 편집에는 [합성 편집 예시](../examples/editing-example.md)의 입력만 사용한다. 자연스러운 문장을 유지하고 수치·행동을 바꾸지 않는지 본다. [집필 예시](../examples/writing-example.md)는 한 가지 가능한 결과이며 정답 문장으로 재현할 필요가 없다.

## 판단

문체는 의미 단위 문단, 자연스러운 호흡, 일관된 목소리, 출처로 인한 흐름 중단, 불필요한 재작성과 반복을 읽고 판단한다. 낯선 주제를 기존 유형에 억지로 맞추지 않는다. 문장 길이·종결어미·AI 탐지 점수에 합격선을 두지 않는다.

사실 검토는 기존 수치·고유명사·조건·출처뿐 아니라 새로 생긴 주장과 1인칭 표현도 대조한다. 원본 근거, 외부 자료, 설명·판단, 작성자 확인 필요, 수정·제거 필요를 구분한다. 다음은 문체 평가와 별도로 보고할 실패다.

- 경험·행동·습관·감정·실측 결과를 지어냄
- 사실·인과관계·수치·적용 범위를 왜곡함
- 중요한 조건·이미지·카드·링크를 기록 없이 잃음
- 승인 없이 CMS를 변경함

자동 검사가 통과해도 사실 검증 완료로 대체하지 않는다. 작성자와 검토자가 같으면 자체 검토임을 밝힌다. 자연스러움의 최종 판단은 원고를 읽는 사용자에게 남긴다.

## 더 큰 변경의 비교 평가

동작을 크게 바꿀 때에만 영향받는 대표 유형부터 비교한다. 자료·모델·설정·조사 조건을 맞추고, 가능하면 새 세션에서 각각 실행한다. 원고의 스킬 이름과 매핑을 숨기지 못했다면 완전한 블라인드 평가라고 부르지 않는다. 매 배포마다 대규모 A/B를 반복하지 않는다.

## 실행 상태 기록

`Passed`, `Failed`, `Not tested`, `Needs verification`으로 관찰한 결과를 기록한다. 모델 실행 없이 폴더만 확인했다면 ‘설치 구조 확인’으로 한정한다. 파일 내용을 직접 제공한 실행은 자동 참조 로딩과 구분한다.

실제 토큰·비용을 확인하지 못했으면 미측정으로 남긴다. 문서 크기를 API 비용 절감률로 환산하지 않는다. 실행 로그와 상세 비용 기록은 공개 패키지에 넣지 않는다. CMS나 실제 기기가 없는 검사는 Ghost 렌더링·실기기 검증을 대신하지 않는다.
